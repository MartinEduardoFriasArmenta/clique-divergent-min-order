# Exhaustive computation on Whitney triangulations of the disk (Section 7, Theorem 7.2)

Programs used to verify, for **all** Whitney triangulations of the disk (flag disks) with at most 18 vertices,
that every disk is K-null and that all its iterated clique graphs are 1-dismantlable.

## Files

| File | Purpose |
|---|---|
| `gen_disks_ca.c` | Generates all flag disks on exactly `n` vertices, up to isomorphism, by McKay's canonical construction path. Every disk is obtained from a disk on `n-1` vertices by adding a vertex adjacent to an induced path of consecutive boundary vertices (Proposition 2.7); isomorphs are rejected with nauty's canonical labeling. Nothing is stored, and the work can be split into independent parts (`gen_disks_ca n res mod`). |
| `gen_disks.c` | Same generation, keeping the disks of each order in a hash table. Used only to cross-check the counts (it agrees with `gen_disks_ca` for n ≤ 15). |
| `kdisk.c` | For each disk `B` computes the 0-cores `H_0 = core(B)`, `H_i = core(K(H_{i-1}))` until some `H_i` is trivial, or a limit on the number of iterations (`-i`) or on `|K(H_{i-1})|` (`-L`) is reached, and certifies that each `H_i` is 1-dismantlable (randomized greedy deletion of 1-dominated vertices, then exact search if needed). By Lemma 7.1, `K^i(B)` is 0-dismantlable iff `H_i = K_1`, and `K^i(B)` is 1-dismantlable whenever `H_i` is. Cliques are enumerated by Bron–Kerbosch with pivoting on bitsets. With `-S` it prints one summary line per run and lists only the exceptional disks (`-O` adds the disks not decided within the limits). |
| `run_exhaustive.sh` | First stage: `gen_disks_ca n r MOD | kdisk -S -O -i 5 -L 2000` for all orders and parts, in parallel and resumable. Writes `out/n<n>_r<r>.sum` (summary), `.tsv.gz` (exceptional and undecided disks) and `.gen` (count). |
| `rerun_open.sh` | Second stage: runs `kdisk -S -O -i 12 -L 3000` again on the disks of each part that were not decided in the first stage; writes `out2/`. |
| `summarize.py` | Merges the summaries of the first stage (`out/`) into `exhaustive_summary.tsv` and `exhaustive_table.tex`, one row per order `n`. |
| `Makefile` | Builds the three C programs. |

## Requirements and build

- A C compiler and nauty with its headers (`apt install nauty libnauty-dev` on Debian/Ubuntu, `brew install nauty` on macOS; `gen_disks_ca.c` and `gen_disks.c` link against `libnautyL1`).
- Python 3 for `summarize.py` (standard library only).

```bash
make
```

## How the computation of the paper was run

```bash
./run_exhaustive.sh 3 18 2          # stage 1: all disks with 3 <= n <= 18, 2 cores, 64 parts per order
python3 summarize.py out            # per-order table of stage 1
./rerun_open.sh 2 12 3000           # stage 2: the disks not decided in stage 1, 12 iterations, |K(H)| <= 3000
```

- Stage 1 (five iterations, `|K(H_{i-1})| <= 2000`): 550,551,244 disks, about five hours on two cores.
  23,935,868 disks were not decided (not K-null within five steps) and 11 exceeded the size limit.
- Stage 2 (twelve iterations, `|K(H_{i-1})| <= 3000`): about two hours. All the disks of stage 2 were decided
  except 28 (n = 18) that exceeded the limit.
- Stage 3: the 39 remaining disks (all with 18 vertices and a boundary of length 4) were run by hand with
  `kdisk -i 12 -L 12000` and, for the last two, `-L 60000`; the largest clique graph computed had 57,768 vertices.

The summary lines of stage 2 (`out2/*.sum`) have the same format as those of stage 1 and were added up
directly to obtain the final table. No undecided case remained: every disk with at most 18 vertices has a
0-dismantlable iterate `K^i(B)` with `i <= 8`, and all the cores along the way are 1-dismantlable.

The results (per-order tables in TSV and LaTeX, the 39 hard disks, and the raw summary lines of every part)
are in `results/exhaustive_disks_n18/` at the root of the repository. The lists of disks not decided in
stage 1 (about 260 MB compressed) are not included; they are regenerated by `run_exhaustive.sh`.

## Checks

- The number of flag disks is 1, 1, 2, 6, 13, 48, 176 for n = 3, ..., 9, in agreement with the exact filter of all
  connected graphs from `geng` used in the preliminary experiment (`../disk_exp.py`); `gen_disks` and `gen_disks_ca`
  give the same numbers for n ≤ 15, and `labelg` finds no duplicates for n ≤ 12.
- `kdisk` reproduces, disk by disk, the outcome of the preliminary Python experiment (`../disk_exp.py`,
  data in `data/disk_results.tsv`) in every case in which the latter reached a decision.

## Reusing the programs

To go beyond n = 18, run `./run_exhaustive.sh 19 19 <cores>`; expect about 2.6 billion disks and roughly
40 core-hours for stage 1, plus a longer stage 2. The number of disks grows by a factor of about 5.7 per vertex.
